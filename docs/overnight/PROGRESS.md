## 단계 1 — 공통 상태·데모 기반 (2026-09-15, claude-opus-5)

### 구현
- **공통 상태 정리**: App 안의 예시 시드(공고·신청·대화방·약속·알림·후기)를 `src/data/prototypeSeed.ts`의 `createSeedData()`로 옮겨 초기 로드와 초기화가 같은 원본을 쓴다. App은 저장본 또는 시드 하나에서 모든 상태를 시작한다.
- **새 타입** (`src/types.ts`): `FavoriteFriend`, `Invitation`(invitationId/postId/senderId/recipientId/receivedAt), `CompletionConfirmation`(개인별), `AppointmentReview`(appointmentId+reviewerId), `NotificationSettings`(처음 보는 사람 초대 알림, 기본 ON), `BlockRelation`, `DemoSettings`(시간 오프셋·02/04/07 A/B). `NotificationItem`에 recipientId/createdAt/targetType/targetId와 초대·새 공고·완료·평가 종류 추가. `CurrentUser`에 birthDate/hobbies/traits/isSample 추가. App 공통 상태로 보유·저장한다.
- **버전 저장소** (`src/utils/prototypeStore.ts`): `yumidang:demo:v1`(체험)과 `yumidang:app:v1`(일반)을 분리. 봉투 `{version, savedAt, data}` + 구조 검증. 손상·다른 버전은 화면을 예시로 살리고 경고를 띄우며, 사용자가 `저장 다시 시도`/`저장 데이터 초기화`를 누르기 전에는 깨진 원본을 덮어쓰지 않는다. 용량 초과는 이전 저장본을 유지하고 안내한다. 300KB 넘는 data: 이미지(사진 원본)는 저장하지 않고 표식으로 바꾼다.
- **명시적 데모** (`src/utils/demoMode.ts`, `src/components/DemoControlPanel.tsx`): `?demo=1`일 때만 상단 노란 `체험 설정` 영역이 보인다(서비스 버튼과 구분). 내용: 현재 역할·한국 시간 표시, 예시 계정 5개와 로그아웃 상태로 역할 전환, +1시간/+1일/+7일/시각 지정/실제 시각 복귀, 02·04·07 A/B 선택, 확인 후 데모 키만 초기화(일반 저장 데이터는 그대로). 역할 전환은 같은 브라우저 저장소 안에서 userId만 바꾸며, 기기 간 동기화가 아니라고 화면에 적었다. 체험 모드는 로그아웃 상태로 시작하므로 기존 헤더 `로그인` 흐름을 그대로 쓸 수 있다.
- **새로고침 보존**: 로그인 역할·현재 탭·공고·신청·대화(초안 포함)·약속·알림·관심친구·초대·완료·평가·알림설정·시간 오프셋·A/B를 저장한다.
- **시간 전환 반영**: `clock()`을 App의 모집 마감·수정·신청·작성자 수락(`acceptRequest`)·대화 접근(`roomAccess`)·재동의·취소·완료/평가 판단에 넘긴다(`conversations.ts`에 선택 인자 `now` 추가, 기본값은 기존 동작).
- **외부 요청 격리**: 데모에서는 Supabase 세션 복원·인증 리스너·로그아웃 호출을 하지 않고, 클라이언트도 세션 저장/자동 갱신을 끈다. `trackFunnelEvent`/`trackBackEvent`는 데모에서 바로 반환한다. 기존 연동 코드는 일반 모드에서 그대로다.
- **당도15·공개정보 공통화** (`src/data/publicProfiles.ts`, `src/data/demoAccounts.ts`): `NEW_USER_SUGAR = 15`. 새 가입자는 고유 `user-<uuid>`, 당도 15, 휴대폰 인증 배지 없음(인증번호 확인이 체험이라서). Supabase 세션 사용자도 15. 로그인은 예시 회원(조*미) 계정 레코드를 그대로 써서 모든 화면의 공개정보가 같다. `publicProfileOf(member, directory)` 하나로 공고·신청·대화·약속 모두에서 같은 사진/소개/취미/당도를 만들고, 전화·실명·생년월일·이메일·추천코드는 넣지 않는다. Me는 `인증 전` 표시와 `합산·하한·갱신 시점은 논의 중` 안내로 바꿨고, 기본 50 기준 증감 문구는 없앴다.
- **권한·관계 함수**: `src/utils/access.ts`(비공개 영역 로그인 요구, 확정·완료 당사자만 상세장소, 수신자 지정 알림 필터 — App 알림 목록·안 읽은 수에 적용), `src/utils/relations.ts`(수신자 기준 저장 여부 AND 실제 동행 여부로 '처음 보는 사람' 판단, 알림설정 기본값).
- **회귀 수정**: 데모 바가 생기면서 채팅 화면 고정 높이(`100dvh-126px`) 때문에 입력창이 하단바 아래로 밀려 `메시지 보내기`를 누를 수 없었다. 패널이 자기 높이를 `--demo-bar-h`로 알리고 ChatView가 그만큼 뺀다.

## 단계 2 — 가입·내 프로필·상대 프로필 (2026-09-15, claude-opus-5)

이전 호출이 사용량 제한으로 끊기기 전에 남긴 부분 구현(아래 파일)을 먼저 검사했다. 타입·단위는 통과했지만 브라우저 검사가 5건 중 4건 FAIL이어서 원인을 고치고 검사를 보강했다.

### 구현 (부분 구현 확인 + 이번 수정)
- **검증 규칙 공통화** (`src/utils/profile.ts`): 전화 숫자만 11자리(입력·붙여넣기 동일, 01로 시작), 한글 실명(자모 낱자/영문·공백·숫자 구분 안내, 2~10자, 저장/다음에서만 검사해 IME 조합 방해 없음), 생년월일(실제 달력 날짜·한국 날짜 기준 미래 차단·만 19세), 공개용 연령대 계산, 남성 추천인 코드/학교·직장 이메일 형식 검사(개인 메일 거부), 사진 JPG/JPEG/PNG·10MB 이하(정확히 10MB 허용), 소개 필수·300자·연락처/메신저/금칙어 안내, 프로필 미완성 단계 계산(저장 차단된 사진 표식은 사진 없음으로 처리), 사진 없는 사용자용 중립 placeholder.
- **01 A 가입** (`src/components/AuthModal.tsx`): 헤더 `로그인` → 팝업 위 탭 없음 → 하단 `휴대폰 본인인증으로 가입` → 약관 → 번호(실제 문자 미발송 안내·예시 코드) → 기본정보(실명·생년월일·성별·지역, 남성은 추천인 코드 또는 학교·직장 이메일 예시 확인) → `로그인으로 돌아가기`. 신규 가입자는 당도 15, 휴대폰/KYC 배지 없음, 생년월일 저장·공개는 연령대만.
- **프로필 만들기/편집** (`src/components/ProfileEditor.tsx`, `src/utils/imageResize.ts`): 첫 가입/미완성 로그인 뒤 사진 → 취미·성향 → 소개 → 확인/저장 4단계. 사진은 선택 → 미리보기(미저장 표시) → `이 사진으로 저장` → 변경/삭제(삭제 확인·재등록 안내). 원본은 저장하지 않고 480px JPEG로 줄여 보관, 손상 파일은 다시 선택 안내. Me `프로필 편집`은 한 번에 저장, 저장하지 않은 변경은 닫을 때 확인. 설정 중·편집 중 모두 `공개 프로필 미리보기`.
- **미완성 복귀** (`src/App.tsx`, `MyPageView.tsx`): 신청·공고 작성 시 첫 미완성 단계로 이동. 이번 수정으로 안내 문구를 전역 알림 대신 편집기 안 경고로 띄운다(전역 알림이 편집기 `다음` 버튼을 가려 누를 수 없던 문제). 상단 미완성 바와 Me 안내에서 `이어서 작성`, 새로고침 뒤에도 남은 단계부터 재개.
- **당도·배지** (`MyPageView.tsx`, `UserProfileModal.tsx`, `KycAuthModal.tsx`): 신규 `15 🍯`·`인증 전`, 샘플 회원은 `샘플 수치`/`예시` 표시, 합산·하한·갱신 논의 중 안내. KYC 창은 흐름 미리보기만 하고 배지를 주지 않으며, 이번에 dialog 역할·닫기 이름·Esc를 추가했다.
- **02 A/B 상대 프로필** (`UserProfileModal.tsx`): A는 사진·이름·지역·연령대·취미·소개(3줄)·당도/후기 요약 후 `상세 펼치기`(aria-expanded), B는 같은 정보를 연속 스크롤. 체험 설정의 02 선택으로 전환(사용자에게 매번 묻지 않음). 관심친구 저장/해제(상대 알림 없음), 신고·차단 진입(`SafetyEntryDialogs.tsx`, 예시 접수·영향 안내). 전화·실명·생년월일·이메일·추천코드는 공개 객체에 복사하지 않는다.
- **진입점**: 공고 상세 작성자 요약, 채팅 헤더, Me 받은/보낸 신청, 약속 대시보드 상대 → 모두 같은 userId로 `publicProfileForMember`. 초대 진입점은 초대 화면이 생기는 단계 4에서 같은 함수로 연결한다.
