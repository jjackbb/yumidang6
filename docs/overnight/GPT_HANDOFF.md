## 다른 DB 세션과 충돌을 피하는 작업 경계

현재 변경 목록과 인증 인수인계 문서에서 확인한 파일이다. 다른 세션의 전체 실시간 작업 범위가 확정됐다는 뜻은 아니다.

| 영역 | 파일 | 이 세션의 처리 |
| --- | --- | --- |
| 다른 세션의 인증·환경 작업 | `src/auth/*`, `src/lib/supabase.ts`, AuthModal/DemoAuthModal/SupabaseAuthModal/AuthGate, `.env*`, package*.json, `vercel.json`, 인증 테스트·docs/auth | 그대로 보존. 되돌리기·중복 구현 금지 |
| 공유 통합 지점 | `src/App.tsx`, 공통 타입·저장소, README | App에는 이미 큰 인증 변경이 있다. 다른 세션 작업 범위를 확인한 뒤 현재 코드에 필요한 변경만 반영. 예전 App 전체 복사 금지 |
| 먼저 분리 가능한 프론트 작업 | 관심친구/초대 정렬·알림 판정의 독립 모듈, 전용 UI, 관련 단위 테스트 | 별도 파일부터 작성하고 props/입출력을 기존 타입에 맞춘다. 기존 파일도 편집 직전 diff를 확인 |
| DB 통합 | 스키마·시드·RLS·Auth·업무 데이터 repository/API | 다른 세션 결과를 받은 뒤 실제 계약 확인. 임의로 새 테이블·RPC 또는 두 번째 DB 저장 계층을 만들지 않음 |

참고: 인증 문서는 현재 대상 프로젝트를 `fiaxchvyywpqbwbcuzfz`로 안내한다. 이전 Supabase 점검 문서의 `hrhudubhmazqevnrfsmo`는 과거 점검 대상이다. 이 세션은 새 대상 DB를 직접 검증하지 않았으므로 과거 주소·키를 복원하거나 새 프로젝트의 DB 구현 완료를 주장하지 않는다.

프로토타입 저장소와 실제 DB 연동을 구별한다. 다른 세션에서 DB를 만들었다고 해서 현재 localStorage 업무 흐름이 자동으로 DB에 저장되는 것은 아니다. 실제 공통 사용자/공고/신청/동행 ID, 상태 전이, 참여자 권한, 저장 실패 응답을 받은 뒤 통합한다. DB 계약이 아직 없으면 확정된 프론트 모듈 작업을 먼저 진행한다.
