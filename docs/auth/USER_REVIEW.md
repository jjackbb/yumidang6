# 테스트 로그인 — 2026-09-15

## 확정한 내용

- 사용자가 선택한 프로젝트: Supabase 계정의 `yumidang` (`fiaxchvyywpqbwbcuzfz`). 로컬 환경변수에 해당 URL과 공개 publishable 키를 설정했다.
- 사용자가 선택한 방식: 휴대폰 인증 → “프로토타입이라서, 테스트 인증번호로 대체해줘”.
- 현재 로컬 `VITE_AUTH_MODE=prototype`: 예시 인증번호 `123456`으로 로그인한다. 실제 SMS, Supabase Auth, 분석 이벤트 요청을 보내지 않는다.

## 바로 확인하기

1. `npm run dev`를 실행하고 `/chat` 또는 `/me`를 연다.
2. 로그인 화면에 채워진 예시 번호 `01000000001`로 **인증번호 발송**을 누른다. 실제 문자는 발송되지 않는다.
3. **테스트코드 입력** 또는 `123456` 입력 → **인증 확인 및 로그인**.
4. 원래 열려고 했던 화면으로 돌아간다. 새로고침해도 이 브라우저의 예시 로그인은 유지된다.
5. Me에서 로그아웃하면 홈으로 이동한다. `/chat`, `/me`를 다시 열면 로그인이 필요하다.

홈(`/`)과 둘러보기(`/explore`)는 공개다. 기존 가입 단계, 프로필 작성, `?demo=1`의 예시 계정 전환도 유지한다.

## 실제 인증과의 차이

현재 테스트 코드는 **브라우저 안에서만 동작하는 모의 인증**이다. Supabase가 발급한 실제 세션이나 서버 데이터의 접근 권한을 뜻하지 않는다. 프로필·공고·채팅 데이터도 기존 로컬 프로토타입 상태다.

Supabase 실제 휴대폰 인증 코드도 별도로 연결했다. 다만 프로젝트의 Phone provider가 현재 비활성화돼 있어 실제 OTP 로그인은 미실행이다. 테스트 전화번호를 Supabase에 등록해 실제 세션을 발급받는 방식도 이번에는 설정하지 않았다.

검증 결과와 실제 모드 전환 조건: [HANDOFF](HANDOFF.md).
